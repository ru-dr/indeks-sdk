# Collector protocol

This is the contract between the Indeks SDK and a collector (the server that receives events). The Indeks dashboard implements it at `POST /api/v1/collect`. You can implement it yourself to send events somewhere else.

## Request

```
POST <endpoint>
Content-Type: text/plain;charset=UTF-8

{"apiKey":"<project key>","events":[ ... ]}
```

- The body is JSON, but the content type is `text/plain`. This keeps the request a CORS "simple request", so browsers do not send a preflight `OPTIONS` request first. A collector must therefore parse the body as JSON regardless of the content type. Requests with `Content-Type: application/json` are also fine.
- The project key is in the body as `apiKey`. A custom header cannot be used because it would trigger a preflight. Collectors may additionally accept an `x-api-key` header.
- `sendBeacon` is used when the page is hidden or unloaded, with the same body and content type.
- A request carries 1 to 100 events. The Indeks collector accepts up to 500.

## Event object

```json
{
  "type": "click",
  "url": "https://example.com/pricing",
  "sessionId": "indeks_1730000000000_ab12cd34ef56a",
  "userId": "0b9f6c0e-8c34-4a43-9a52-3f0f4c5d2a11",
  "userAgent": "Mozilla/5.0 ...",
  "referrer": "https://news.example.org/",
  "timestamp": 1730000000123,
  "properties": {
    "element": { "tagName": "button", "className": "cta", "id": "buy", "textContent": "Buy now", "attributes": {} },
    "coordinates": { "x": 120, "y": 480, "clientX": 120, "clientY": 300 }
  }
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `type` | string | Required, 1 to 256 characters |
| `url` | string | Scrubbed page URL |
| `sessionId`, `userId` | string | Anonymous identifiers generated by the SDK |
| `userAgent` | string | Collectors derive browser, OS and device from this |
| `referrer` | string | Optional, scrubbed |
| `timestamp` | number | Milliseconds since the epoch |
| `properties` | object | Everything else for that event type, including `externalUserId` when `identify()` was called |

Fields of each event type are listed in [events.md](events.md). Values that look sensitive are removed or replaced with `[redacted]` before the request is made.

## Response and retries

| Status | SDK behavior |
| --- | --- |
| 2xx | Success, events are discarded from the queue |
| 408, 429, 5xx, network error | Retry the same events with exponential backoff (1 s base, 30 s cap, jittered). Events stay queued, up to 1000 |
| Other 4xx (invalid key, bad request) | The batch is dropped and not retried |

The SDK does not read `Retry-After`. Responses to `sendBeacon` are not visible to the page. If the browser is offline, events are stored in `localStorage` (newest 500) and sent on the next visit.

## CORS requirements for a custom collector

```
Access-Control-Allow-Origin: *
```

That is enough for the `POST`. Because the request is simple, no `OPTIONS` handler is required, although answering one does no harm.

## Minimal collector (Node)

```js
import { createServer } from "node:http";

createServer(async (req, res) => {
  res.setHeader("Access-Control-Allow-Origin", "*");
  if (req.method !== "POST") return res.writeHead(204).end();
  let raw = "";
  for await (const chunk of req) raw += chunk;
  const { apiKey, events } = JSON.parse(raw);
  console.log(apiKey, events.length, "events");
  res.writeHead(200, { "content-type": "application/json" }).end('{"success":true}');
}).listen(8787);
```
